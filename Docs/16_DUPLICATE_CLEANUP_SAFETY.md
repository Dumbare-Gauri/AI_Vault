# 16 — Duplicate Cleanup Safety (Planned Feature)

**Status:** Planned, not started. Logged 2026-10-08.

## What happened

On 2026-10-08 the founder asked the AI assistant to move all duplicate files to trash. The local agent connected to `C:\Projects` carried this out and trashed **616 files** between 06:45 and 06:56 UTC:

| Project folder | Files trashed |
|---|---|
| TFW_WEB | 296 |
| GFE | 123 |
| Audio | 75 |
| TFW_DOCS | 38 |
| AI_Vault | 37 |
| WIZ_Port | 22 |
| Glued | 13 |
| Others (6 folders) | 13 |

The files went to the Recycle Bin, so they can be recovered. The cleanup did what it was asked to do. The problem is that **files with identical content are not always unwanted copies.** Some of them have to exist where they are, and removing them broke the projects that rely on them.

## Files that must not be treated as duplicates

Files from the AI_Vault folder that were trashed and that the project needs:

- **Empty files.** Every empty file has the same checksum, so every empty `__init__.py` matched every other one. Python needs these files to treat a folder as a package. Without them, imports fail and the backend, worker and tests can't run. `py.typed` markers were removed the same way.
- **Environment files.** `apps/backend/.env` and `apps/worker/.env` held identical settings, so one copy counted as a duplicate. These files carry secrets and configuration that the app needs where they are.
- **Infrastructure files.** `.terraform.lock.hcl` and `outputs.tf` in the production terraform folder.
- **Static assets.** `apps/frontend/public/vault.svg`.
- **Build output.** Files under `apps/frontend/dist/`. These are harmless to remove because they are regenerated by the build.

AI_Vault was recovered by restoring the tracked files from git. The other projects were not checked and may be broken in the same way.

## Feature to build

Before the AI moves any duplicate to trash, it must decide whether that copy is **required in its location**. "Same content" alone is not enough.

### 1. Never treat these as duplicates

- Empty (0-byte) files
- Package and module markers: `__init__.py`, `py.typed`, `.gitkeep`, `.keep`
- Environment and secret files: `.env`, `.env.*`, `*.pem`, `*.key`
- Lock and manifest files: `package.json`, `pnpm-lock.yaml`, `package-lock.json`, `requirements*.txt`, `pyproject.toml`, `*.lock`, `.terraform.lock.hcl`
- Infrastructure and config: `*.tf`, `Dockerfile*`, `docker-compose*.yml`, `.gitignore`, `.github/**`
- Any file under a version-controlled folder (one that contains `.git`), unless the user asks for that folder by name

### 2. Recognise project folders

If a folder looks like a code project (it contains `.git`, `package.json`, `pyproject.toml` or similar), copies inside it are probably intentional. In that case the AI should either:
- skip the copies inside it, or
- show them as "needs review" instead of including them in a bulk cleanup.

### 3. Confirm before bulk cleanup

When a cleanup is about to trash more than a set number of files (for example 50), or touches files inside a project folder, the AI shows a summary first:
- how many files are affected, grouped by folder
- which of them are protected file types

The user then confirms before anything is moved.

### 4. Make every cleanup reversible as one unit

Keep a record of each cleanup run: what was trashed, when, and from where. Provide a single "Undo this cleanup" action that restores every file in that run. Today the only record is the `agent_commands` table, and restoring means going through the Recycle Bin one file at a time.

### 5. Explain why each file is a duplicate

Each duplicate group should show the reason it matched (identical checksum) and which copy is kept. Empty files must be flagged so the user can see the matches are only empty files.

## Where this lives in the code today

- Duplicate detection: [duplicate_detector.py](../apps/worker/worker/storage_intelligence/duplicate_detector.py) groups files only by content checksum. The only thing it skips is groups larger than 200 files.
- Local agent trash commands are recorded in the `agent_commands` table (`op = 'trash'`).

## Open questions

- Should the protected list be fixed in code, or editable per organization?
- Should project-folder detection skip those folders entirely, or only exclude them from bulk actions?
